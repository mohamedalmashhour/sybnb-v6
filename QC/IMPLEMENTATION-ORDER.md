# Delivery order — one reviewable milestone at a time

## QRide first

1. QC source workspace, shared capsule wiring and licensing evidence register (this phase).
2. Isolated Canada backend boundary; persistent account applications and authorized
   driver/admin provisioning. Reject unapproved/expired drivers on the server.
3. Coverage and Maps/route integration; server-issued expiring CAD quotes with approved
   categories, taxi treatment, taxes, fees, commission base and dynamic-price caps.
4. Atomic dispatch/acceptance, arrival/boarding/completion, persistent trip/safety records.
5. Approved provider sandbox, idempotent payment/refund/receipt and driver reconciliation.
6. Verify regulatory, insurance, tax/billing, privacy/security and support evidence;
   prepare a concrete application package for authorized review/submission.

## QTR second

1. QC source workspace, CAD placeholder correction and separate licensing register (this phase).
2. Persistent guest/host accounts and verified property eligibility/documents.
3. Real search, listing details, capacity, host calendar and atomic booking holds.
4. CAD itemized quotes, applicable taxes, cancellation terms and provider sandbox checkout.
5. Confirmation, messages, arrival/departure, refunds, incidents and host payouts.
6. Verify property/municipal and platform-specific obligations; prepare review/submission package.

Each milestone needs focused browser/API checks, concurrency/retry/rejection tests
where relevant, and the governed regression. Keep the existing 12 failing suites
visible until fixed. A working screen or competitor-like journey is not a licence.
Uber/Airbnb are product benchmarks, not a source of transferable authorizations.
